## 네트워크 장비와 ARP/RARP 프로토콜

### 핵심 개념
ARP(Address Resolution Protocol)는 IP 주소를 MAC(물리) 주소로 변환하고, RARP는 그 반대로 동작한다. 네트워크 장비는 동작하는 OSI 계층에 따라 역할이 구분되며, 허브(1계층)→스위치(2계층)→라우터(3계층)→게이트웨이(4~7계층) 순으로 처리 지능이 높아진다.

### 키워드

**ARP / RARP**

| 프로토콜 | 방향 | 설명 |
|---------|------|------|
| **ARP** | IP → MAC | 동일 네트워크 내 통신 시 목적지 MAC 주소 확인 (브로드캐스트로 질의) |
| **RARP** | MAC → IP | 디스크 없는 워크스테이션이 부팅 시 자신의 IP 주소 획득 |
| **Proxy ARP** | — | 라우터가 다른 네트워크 호스트 대신 ARP에 응답 |
| **Gratuitous ARP** | — | 자신의 IP/MAC을 스스로 알림 (IP 충돌 감지, HSRP 전환) |

**네트워크 장비 비교**

| 장비 | OSI 계층 | 기능 | 특징 |
|------|---------|------|------|
| **허브(Hub)** | 1계층 (물리) | 신호 증폭/분배 | 모든 포트로 브로드캐스트, 충돌 발생 |
| **스위치(Switch)** | 2계층 (데이터링크) | MAC 주소 기반 프레임 전달 | MAC 테이블로 포트 학습, 충돌 도메인 분리 |
| **라우터(Router)** | 3계층 (네트워크) | IP 주소 기반 패킷 라우팅 | 브로드캐스트 도메인 분리, 서브넷 간 연결 |
| **게이트웨이(Gateway)** | 4~7계층 | 프로토콜 변환 | 이기종 네트워크 연결, 모든 계층 처리 |
| **브리지(Bridge)** | 2계층 (데이터링크) | 두 네트워크 세그먼트 연결 | 스위치의 전신, MAC 기반 필터링 |

**패킷 교환 방식**

| 방식 | 특징 |
|------|------|
| **가상회선(Virtual Circuit)** | 경로를 미리 설정 후 전송, 순서 보장, 연결 지향 |
| **데이터그램(Datagram)** | 패킷마다 독립 경로 선택, 순서 미보장, 비연결 지향 |

### ARP 동작 과정
```
1. 호스트 A가 호스트 B의 IP는 알지만 MAC 모름
2. A가 브로드캐스트로 ARP Request 전송: "192.168.1.2의 MAC 주소는?"
3. 네트워크의 모든 호스트 수신
4. 해당 IP(B)만 ARP Reply로 자신의 MAC 주소 응답 (유니캐스트)
5. A가 ARP 캐시에 IP-MAC 매핑 저장
```

### 기출 포인트
> **2025-1회**: ARP/RARP 방향 구분 출제 — "IP→MAC은 ARP, MAC→IP는 RARP"
> **2024-2회**: 패킷 교환 방식 출제 — 가상회선 vs 데이터그램 특징 비교
> **장비 구분 핵심**: 스위치=MAC(2계층), 라우터=IP(3계층) — 계층으로 구분
> **브로드캐스트 도메인**: 라우터가 분리, 허브/스위치는 같은 도메인 내 동작

### 연결 개념
- 관련 카드: `nw-protocol-001` (OSI 7계층 — 각 장비의 계층 위치)
- 관련 카드: `nw-routing-001` (라우팅 프로토콜 — 라우터의 경로 결정)
- 관련 카드: `nw-subnet-001` (서브넷팅 — 라우터가 분리하는 네트워크 단위)
