## 테스트 레벨과 통합 테스트 방식

### 핵심 개념
소프트웨어 테스트는 단위→통합→시스템→인수 순서의 4단계 레벨로 진행된다. 특히 통합 테스트에서는 모듈 간 인터페이스 결함을 발견하기 위해 하향식, 상향식, 빅뱅, 샌드위치 방식을 적용한다. 각 방식의 특징과 사용하는 대체 모듈(스텁/드라이버)을 정확히 구분해야 한다.

### 키워드
- **단위 테스트(Unit Test)**: 개별 모듈·함수 단위로 테스트. 개발자가 수행. 코드 결함 조기 발견
- **통합 테스트(Integration Test)**: 모듈 간 인터페이스 및 상호작용 검증. **하향식(Top-Down)** — 상위 모듈부터 통합, **스텁(Stub)** 사용(미완성 하위 모듈 대체). **상향식(Bottom-Up)** — 하위 모듈부터 통합, **드라이버(Driver)** 사용(미완성 상위 모듈 대체). **빅뱅** — 모든 모듈 한꺼번에 통합(결함 위치 파악 어려움). **샌드위치(혼합식)** — 하향식+상향식 병행
- **시스템 테스트(System Test)**: 완성된 시스템 전체를 대상으로 요구사항 명세 기반 테스트. 기능/비기능(성능, 보안, 안정성) 테스트 포함
- **인수 테스트(Acceptance Test)**: 최종 사용자가 수행. **알파 테스트**(개발자 환경에서 사용자가 수행), **베타 테스트**(실제 운영 환경에서 사용자가 수행)
- **회귀 테스트(Regression Test)**: 수정 후 기존 기능에 영향이 없는지 확인하는 반복 테스트

### 기출 포인트
> **스텁(Stub)과 드라이버(Driver)**의 차이는 거의 매회 출제된다. 하향식=스텁, 상향식=드라이버를 반드시 암기해야 한다. 알파 테스트와 베타 테스트의 수행 환경 차이(개발환경 vs 실제환경)를 묻는 문제, 통합 테스트 방식의 장단점 비교 문제도 빈출된다. 회귀 테스트의 정의를 빈칸으로 묻는 문제도 주의해야 한다.
