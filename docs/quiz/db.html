정규화 ★★★★

다음은 정규화 과정이다. 각 정규형의 조건에 해당하는 괄호를 채우시오.

비정규 릴레이션
   ↓ ( ① )을/를 제거
제1정규형(1NF)
   ↓ ( ② )을/를 제거
제2정규형(2NF)
   ↓ ( ③ )을/를 제거
제3정규형(3NF)
   ↓ ( ④ )을/를 제거
BCNF

정답 및 해설 보기
① 반복 그룹(도메인이 원자값이 아닌 것)
② 부분 함수 종속(Partial Functional Dependency)
③ 이행 함수 종속(Transitive Functional Dependency)
④ 결정자이면서 후보키가 아닌 것
핵심: 정규화 단계별 제거 대상 — "도부이결다조"
• 1NF: 모든 속성의 도메인이 원자값(Atomic Value)이어야 함. 반복 그룹 제거
• 2NF: 1NF + 부분 함수 종속 제거. 기본키의 일부에만 종속되는 속성 분리
• 3NF: 2NF + 이행 함수 종속 제거. A→B→C에서 A→C 간접 종속 제거
• BCNF: 3NF + 모든 결정자가 후보키이어야 함
• 4NF: BCNF + 다치 종속(MVD) 제거
• 5NF: 4NF + 조인 종속(JD) 제거

트랜잭션의 4대 특성인 ACID에 대해 각각의 영문 명칭과 의미를 쓰시오.

A - (     ): 트랜잭션의 연산은 모두 실행되거나 모두 실행되지 않아야 한다. (All or Nothing)
C - (     ): 트랜잭션 실행 전후의 데이터베이스 상태가 일관되어야 한다.
I - (     ): 동시에 실행되는 트랜잭션들이 서로 간섭해서는 안 된다.
D - (     ): 트랜잭션이 성공적으로 완료되면 그 결과는 영구적으로 반영된다.

정답 및 해설 보기
A - 원자성(Atomicity)
C - 일관성(Consistency)
I - 독립성/격리성(Isolation)
D - 지속성/영속성(Durability)
핵심: ACID는 트랜잭션의 안전한 수행을 보장하는 4대 특성
• 원자성: Commit(완료) 또는 Rollback(취소). 부분 실행 불가
• 일관성: 무결성 제약 조건을 항상 만족
• 독립성: 병행 제어(Concurrency Control)로 보장. 로킹, 타임스탬프 등
• 지속성: 회복(Recovery) 기법으로 보장. 로그 파일 활용

문제 7
인덱스(Index) ★★★

다음 설명에 해당하는 인덱스 유형의 이름을 쓰시오.

(1) 트리 구조를 사용하며, 루트→중간→리프 노드로 구성된다. 리프 노드가 연결 리스트로 연결되어 있어 범위 검색에 효율적이며, 삽입·삭제 시 균형을 유지하는 인덱스이다.

(2) 해시 함수를 사용하여 키 값을 버킷 주소로 변환하는 방식으로, 동등 비교(=) 검색에 매우 빠르지만 범위 검색에는 부적합한 인덱스이다.

(3) 인덱스의 순서에 따라 데이터의 물리적 저장 순서가 결정되며, 테이블당 하나만 생성할 수 있는 인덱스이다.

정답 및 해설 보기
(1) B-Tree(B트리) 인덱스
(2) 해시(Hash) 인덱스
(3) 클러스터드(Clustered) 인덱스
핵심: 인덱스 유형별 특성 비교
• B-Tree: 대부분의 DBMS 기본 인덱스. O(log N) 검색. 범위/정렬 검색 가능
• B+Tree: B-Tree의 변형. 리프 노드에만 데이터, 리프 간 연결 리스트
• 해시: O(1) 검색. =, IN 조건에 최적. >, <, BETWEEN 불가
• 클러스터드: 물리적 정렬 = 인덱스 순서. 테이블당 1개. 영어사전과 유사
• 넌클러스터드: 별도의 인덱스 페이지 사용. 테이블당 여러 개 가능. 책 뒤의 색인과 유사
문제 8
복구 기법 ★★★

데이터베이스 회복(Recovery) 기법에 관한 다음 괄호를 채우시오.

(1) (     ): 트랜잭션이 완료(Commit)되었으나 DB에 반영되지 않은 경우, 로그를 이용하여 변경 내용을 다시 실행하는 기법

(2) (     ): 트랜잭션이 완료되지 않은 상태에서 장애가 발생한 경우, 로그를 이용하여 변경 내용을 이전 상태로 복원하는 기법

(3) (     ): 일정 주기로 DB의 상태를 저장해두고, 장애 발생 시 가장 최근 (     ) 이후의 로그만 처리하여 회복 시간을 단축하는 기법

정답 및 해설 보기
(1) REDO(재실행)
(2) UNDO(취소/복원)
(3) 검사점(Checkpoint) 회복 기법
핵심: 회복 기법 분류
• REDO: Commit O + DB 반영 X → 재실행. "앞으로(Forward) 회복"
• UNDO: Commit X + DB 반영 O → 취소. "뒤로(Backward) 회복"
• 검사점: 주기적으로 Checkpoint 기록 → 장애 시 Checkpoint 이후만 처리
• 그림자 페이징: 로그 대신 그림자 페이지 테이블 사용. UNDO 불필요
• 로그 기반 회복: 즉시 갱신(Immediate Update), 지연 갱신(Deferred Update)
• 지연 갱신: Commit 전까지 DB에 반영 안 함 → UNDO 불필요, REDO만 필요

(2) 스키마 없음(Schema-less), 수평적 확장(Scale-out) 용이, 대용량 비정형 데이터 처리에 적합, ACID 대신 BASE 모델(Basically Available, Soft state, Eventually consistent)
핵심: RDB vs NoSQL 비교
• RDB: 정형 데이터, 스키마 필수, JOIN 지원, ACID 보장, 수직 확장(Scale-up)
• NoSQL: 비정형/반정형 데이터, 스키마 유연, JOIN 미지원(대부분), BASE, 수평 확장(Scale-out)
• 키-값: 가장 단순. 캐시, 세션 관리에 적합
• 문서: JSON/BSON 형태 저장. 유연한 스키마
• 컬럼: 대량 데이터 집계에 적합. 행이 아닌 컬럼 단위 저장
• 그래프: 노드와 엣지로 관계 표현. SNS, 추천 시스템에 적합
