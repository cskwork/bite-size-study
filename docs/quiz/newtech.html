클라우드 컴퓨팅 ★★★

다음 클라우드 컴퓨팅 서비스 모델 비교표의 빈칸을 채우시오.

/* 클라우드 서비스 모델 비교 */

┌──────────┬──────────────────────────┬─────────────────┐
│ 서비스모델 │          설명            │     예시         │
├──────────┼──────────────────────────┼─────────────────┤
│  (  ①  ) │ 서버, 스토리지, 네트워크   │ AWS EC2,        │
│          │ 등 (  ②  )을/를 제공     │ Azure VM        │
├──────────┼──────────────────────────┼─────────────────┤
│  (  ③  ) │ 개발에 필요한 (  ④  )을/를│ Google App      │
│          │ 제공 (OS, 미들웨어 포함)  │ Engine, Heroku  │
├──────────┼──────────────────────────┼─────────────────┤
│  (  ⑤  ) │ 완성된 (  ⑥  )을/를     │ Google Docs,    │
│          │ 인터넷으로 제공           │ Office 365      │
├──────────┼──────────────────────────┼─────────────────┤
│  (  ⑦  ) │ 자체 데이터센터에서       │ 기업 전산실      │
│          │ 직접 운영하는 방식        │                 │
└──────────┴──────────────────────────┴─────────────────┘

/* 관리 범위 비교 */
               사용자가 관리하는 영역
온프레미스:    전부 (네트워크~애플리케이션)
IaaS:        (  ⑧  ) 부터 위로
PaaS:        (  ⑨  ) 만
SaaS:        (  ⑩  )
정답 및 해설 보기
① IaaS(Infrastructure as a Service) ② IT 인프라
③ PaaS(Platform as a Service) ④ 플랫폼(개발 환경)
⑤ SaaS(Software as a Service) ⑥ 소프트웨어(응용프로그램)
⑦ 온프레미스(On-Premise)
⑧ OS/미들웨어/런타임 ⑨ 데이터와 애플리케이션 ⑩ 없음(모두 제공자가 관리)
핵심: 클라우드 서비스는 제공 수준에 따라 IaaS → PaaS → SaaS로 분류됩니다.
• IaaS: 인프라(서버, 스토리지, 네트워크)만 제공 → 사용자가 OS부터 직접 설치·관리
• PaaS: 플랫폼(OS+미들웨어+런타임)까지 제공 → 개발자는 코드만 작성
• SaaS: 완성된 소프트웨어를 제공 → 사용자는 바로 사용
• 온프레미스: 자체 서버실에 직접 구축·운영 (클라우드의 반대 개념)
시험 포인트: IaaS/PaaS/SaaS 영문 풀네임과 각각의 예시를 함께 암기하세요!
문제 2
빅데이터 ★★★

다음 빅데이터의 특성과 분석 기술에 대한 빈칸을 채우시오.

/* 빅데이터 3V + 확장 특성 */

빅데이터의 3대 특성(3V):
  ① (     ): 데이터의 양(규모)이 방대함 → 테라~페타바이트급
  ② (     ): 데이터 생성·수집·처리 (     )가 빠름
  ③ (     ): 정형·반정형·비정형 등 데이터 유형이 (     )

확장된 특성:
  ④ (     ): 데이터의 정확성·신뢰성
  ⑤ (     ): 데이터로부터 창출되는 가치

/* 빅데이터 분석 기술 */

┌──────────────┬────────────────────────────────┐
│   기술명      │           설명                  │
├──────────────┼────────────────────────────────┤
│   (  ⑥  )   │ 대용량 데이터 분산 처리 프레임워크 │
│              │ (HDFS + MapReduce)              │
├──────────────┼────────────────────────────────┤
│   (  ⑦  )   │ 대규모 데이터를 빠르게 분석하는   │
│              │ 인메모리 기반 처리 엔진           │
├──────────────┼────────────────────────────────┤
│   (  ⑧  )   │ 대량의 데이터에서 유용한 패턴과   │
│              │ 규칙을 자동으로 발견하는 기법      │
└──────────────┴────────────────────────────────┘
정답 및 해설 보기
① Volume(규모/양) ② Velocity(속도) — 속도 ③ Variety(다양성) — 다양함
④ Veracity(정확성) ⑤ Value(가치)
⑥ 하둡(Hadoop) ⑦ 스파크(Spark) ⑧ 데이터마이닝(Data Mining)
핵심: 빅데이터의 3V는 가장 기본적인 출제 포인트입니다.
• Volume: 수십 테라바이트~페타바이트 이상의 대규모 데이터
• Velocity: 실시간 스트리밍, SNS 등 빠르게 생성되는 데이터
• Variety: 텍스트, 이미지, 영상, 로그 등 다양한 형태
• Hadoop: HDFS(분산파일시스템) + MapReduce(분산처리) 기반 프레임워크
• Spark: Hadoop보다 최대 100배 빠른 인메모리 처리 엔진
함정: 3V에서 5V로 확장 시 Veracity(정확성)와 Value(가치)가 추가됩니다.

다음 IoT(사물인터넷) 관련 용어의 빈칸을 채우시오.

/* IoT 프로토콜 비교 */

┌──────────┬──────────────────────────────────┐
│ 프로토콜  │              특징                 │

│          │ 저전력·저대역폭 환경에 적합        │
├──────────┼──────────────────────────────────┤
│  (  ③  ) │ (  ④  ) 기반 경량 프로토콜        │
│          │ RESTful 구조, 센서 네트워크에 적합  │
└──────────┴──────────────────────────────────┘

/* 컴퓨팅 위치에 따른 분류 */

┌─────────────┬──────────────────────────────────┐
│   용어       │              설명                 │
├─────────────┼──────────────────────────────────┤
│ 클라우드     │ 중앙 데이터센터에서 처리            │
│ 컴퓨팅      │                                   │
├─────────────┼──────────────────────────────────┤
│   (  ⑤  )  │ 네트워크 (  ⑥  )에서 데이터를     │
│   컴퓨팅    │ 처리 → 지연시간 최소화             │
├─────────────┼──────────────────────────────────┤
│   (  ⑦  )  │ 클라우드와 엣지의 (  ⑧  ) 에서    │

└─────────────┴──────────────────────────────────┘
정답 및 해설 보기
① MQTT(Message Queuing Telemetry Transport) ② Publish/Subscribe(발행/구독)
③ CoAP(Constrained Application Protocol) ④ UDP
⑤ 엣지(Edge) ⑥ 가장자리(끝단/엣지) ⑦ 포그(Fog) ⑧ 중간
핵심: IoT 통신 프로토콜과 컴퓨팅 패러다임을 구분하세요.
• MQTT: 브로커 기반 Pub/Sub 모델, QoS 3단계(0,1,2) 지원, 저전력 센서에 적합
• CoAP: UDP 기반, HTTP와 유사한 REST 방식, 제한된 환경(Constrained)에 최적화
• 엣지 컴퓨팅: 데이터 발생 지점(엣지)에서 직접 처리 → 초저지연, 자율주행 등에 활용
• 포그 컴퓨팅: 시스코가 제안, 클라우드-엣지 중간 계층에서 분산 처리
함정: MQTT는 TCP 기반, CoAP는 UDP 기반 — 전송 계층이 다릅니다!

문제 5
블록체인 ★★★

다음 블록체인 관련 용어의 빈칸을 채우시오.

/* 블록체인 핵심 개념 */

블록체인이란?
→ 거래 정보를 (  ①  ) 구조로 연결하여
  (  ②  ) 네트워크에 분산 저장하는 기술

핵심 구성 요소:
┌───────────────┬───────────────────────────────┐
│    용어        │           설명                 │
├───────────────┼───────────────────────────────┤
│   (  ③  )     │ 모든 참여자가 동일한 거래 장부를 │
│               │ 공유·관리하는 분산 데이터베이스   │
├───────────────┼───────────────────────────────┤
│   (  ④  )     │ 블록 생성 시 참여자들이 거래의   │
│               │ 유효성에 합의하는 메커니즘        │
│               │ 예: PoW, PoS, PBFT             │
├───────────────┼───────────────────────────────┤
│   (  ⑤  )     │ 블록체인 위에서 자동 실행되는    │
│               │ 프로그래밍 가능한 (  ⑥  )       │
│               │ 대표 플랫폼: (  ⑦  )           │
└───────────────┴───────────────────────────────┘

/* 합의 알고리즘 비교 */
(  ⑧  ): 작업증명 — 채굴(연산력) 기반, 비트코인
(  ⑨  ): 지분증명 — 보유 지분에 비례하여 검증 권한
(  ⑩  ): 실용적 비잔틴 장애 허용 — 하이퍼레저
정답 및 해설 보기
① 블록(Block) 체인(Chain) ② P2P(Peer-to-Peer)
③ 분산원장(Distributed Ledger) ④ 합의 알고리즘(Consensus Algorithm)
⑤ 스마트 컨트랙트(Smart Contract) ⑥ 계약(디지털 계약) ⑦ 이더리움(Ethereum)
⑧ PoW(Proof of Work) ⑨ PoS(Proof of Stake) ⑩ PBFT(Practical Byzantine Fault Tolerance)
핵심: 블록체인의 3대 구성요소: 분산원장, 합의알고리즘, 스마트컨트랙트
• 분산원장: 중앙 기관 없이 모든 참여 노드가 동일한 원장을 보유
• 합의 알고리즘: 새 블록의 유효성을 네트워크 참여자들이 합의하는 방식
• 스마트 컨트랙트: 조건 충족 시 자동 실행되는 코드 — 중개자 불필요
• PoW vs PoS: PoW는 에너지 소모가 크고, PoS는 지분 기반으로 효율적
함정: 이더리움은 PoW에서 PoS로 전환했습니다(이더리움 2.0). 비트코인은 여전히 PoW입니다.

/* DevOps 핵심 용어 */

DevOps란?
→ (  ①  )팀과 (  ②  )팀의 협업·자동화를 통해
  소프트웨어 배포 주기를 단축하는 문화/방법론

┌──────────────┬────────────────────────────────┐

├──────────────┼────────────────────────────────┤
│   (  ⑤  )    │ 검증된 코드를 자동으로 운영 환경에│

│              │ 대표 도구: (  ⑧  )              │
├──────────────┼────────────────────────────────┤
│   (  ⑨  )    │ 다수의 컨테이너를 자동 배포·확장  │
│              │ ·관리하는 (  ⑩  ) 도구           │

정답 및 해설 보기
① 개발(Development) ② 운영(Operations)
③ CI(Continuous Integration, 지속적 통합) ④ 메인 저장소(공유 저장소)
⑤ CD(Continuous Deployment/Delivery, 지속적 배포) ⑥ 배포(Deploy)
⑦ 컨테이너(Container) ⑧ 도커(Docker)
⑨ 컨테이너 오케스트레이션(Container Orchestration) ⑩ 오케스트레이션
⑪ 마이크로서비스(Microservice) ⑫ 모놀리식(Monolithic)
핵심: DevOps = Development + Operations, CI/CD 파이프라인이 핵심
• CI: 개발자가 코드를 푸시하면 자동 빌드·테스트 수행 (Jenkins, GitLab CI 등)
• CD: CI 통과 후 자동으로 스테이징/운영 환경에 배포
• 도커: 컨테이너 기반 가상화, VM보다 가볍고 빠름, Dockerfile로 이미지 생성
• 쿠버네티스: 컨테이너 자동 스케일링, 로드밸런싱, 롤링 업데이트 지원
• MSA: 각 서비스가 독립 배포 가능, API로 통신, 장애 격리 용이
시험 단골: CI/CD 풀네임, 도커 vs VM 차이, MSA vs 모놀리식 비교 — 반드시 암기!
문제 7
보안 용어 ★★★

다음 보안 관련 신기술 용어의 설명을 읽고 해당하는 용어를 쓰시오.

/* 보안 위협 및 대응 기술 */

(  ①  ):
  '아무도 신뢰하지 않는다'는 원칙에 기반한 보안 모델
  내부·외부 구분 없이 모든 접근에 대해 (  ②  )을 수행

(  ③  ):
  소프트웨어 취약점이 발견된 후 패치가 배포되기
  (  ④  )에 해당 취약점을 악용하는 공격

(  ⑤  ):
  Advanced Persistent Threat의 약자
  특정 대상을 목표로 (  ⑥  )적이고 지속적인 공격 수행
  주로 국가 기관, 대기업 대상

(  ⑦  ):
  시스템을 감염시켜 파일을 (  ⑧  )하고
  복호화 대가로 금전(암호화폐)을 요구하는 악성코드

(  ⑨  ):
  신뢰할 수 있는 기관을 사칭하여
  개인정보·금융정보를 (  ⑩  )하는 사회공학적 공격
정답 및 해설 보기
① 제로트러스트(Zero Trust) ② 인증·검증(Verify)
③ 제로데이 공격(Zero-Day Attack) ④ 전(0일, 패치 전)
⑤ APT(지능형 지속 위협) ⑥ 지능적(고도화된/계획적)
⑦ 랜섬웨어(Ransomware) ⑧ 암호화(Encrypt)
⑨ 피싱(Phishing) ⑩ 탈취(유출/빼내는)
핵심: 보안 위협 유형과 대응 기술을 정확히 구분하세요.
• 제로트러스트: "Never Trust, Always Verify" — 네트워크 위치에 관계없이 항상 검증
• 제로데이: 취약점 발견~패치 배포 사이의 0일 동안 공격 → 방어가 매우 어려움
• APT: 사회공학+제로데이+백도어 등 복합적 기법으로 장기간 침투
• 랜섬웨어: Ransom(몸값) + Malware → 워너크라이(WannaCry)가 대표적
• 피싱: 이메일·문자로 가짜 사이트 유도 → 스미싱(SMS+Phishing)도 포함
추가 용어: 스피어피싱(특정 대상), 파밍(DNS 변조), 스니핑(도청)도 함께 암기!
문제 8
소프트웨어 아키텍처 ★★★

다음 소프트웨어 아키텍처 관련 빈칸을 채우시오.

/* 소프트웨어 아키텍처 비교 */

┌──────────────┬─────────────────────────────────┐
│  아키텍처     │            특징                  │
├──────────────┼─────────────────────────────────┤
│  (  ①  )     │ 하나의 큰 애플리케이션으로 개발    │
│  아키텍처     │ 장점: 단순, 일관성               │
│              │ 단점: (  ②  ), 확장 어려움        │
├──────────────┼─────────────────────────────────┤
│  (  ③  )     │ 작은 독립 서비스들로 분리하여 개발  │
│  아키텍처     │ 각 서비스는 (  ④  )로 통신        │
│              │ 독립 배포·확장 가능               │
├──────────────┼─────────────────────────────────┤
│  (  ⑤  )     │ 서버 관리 없이 코드(함수) 단위로   │
│              │ 실행되는 클라우드 컴퓨팅 모델       │
│              │ 예: AWS (  ⑥  ), Azure Functions │
├──────────────┼─────────────────────────────────┤
│  (  ⑦  )     │ 모든 API 요청의 단일 진입점 역할   │
│              │ (  ⑧  ), 인증, 로깅, 로드밸런싱   │
│              │ 수행                             │
└──────────────┴─────────────────────────────────┘

/* 서비스 간 통신 방식 */
동기 방식: (  ⑨  ) — 요청-응답, HTTP/REST 기반
비동기 방식: (  ⑩  ) — 메시지 큐(Kafka, RabbitMQ) 활용
정답 및 해설 보기
① 모놀리식(Monolithic) ② 부분 수정이 전체에 영향(높은 결합도)
③ 마이크로서비스(Microservice) ④ API(REST API 등)
⑤ 서버리스(Serverless) ⑥ Lambda
⑦ API 게이트웨이(API Gateway) ⑧ 라우팅(요청 분배)
⑨ 동기 통신(Synchronous) ⑩ 비동기 통신(Asynchronous)
핵심: 모놀리식 → 마이크로서비스로의 전환이 최근 트렌드입니다.
• 모놀리식: 모든 기능이 하나의 코드베이스 — 소규모 프로젝트에 적합
• 마이크로서비스: 서비스별 독립 DB, 독립 배포 — 넷플릭스, 아마존 등이 채택
• 서버리스: FaaS(Function as a Service), 사용한 만큼만 과금, 자동 스케일링
• API 게이트웨이: 클라이언트↔마이크로서비스 사이의 중간 관문 역할
함정: 서버리스는 서버가 "없는 것"이 아니라 서버 관리를 "안 하는 것"입니다!
문제 9
데이터 관련 ★★★

다음 데이터 관리 및 분석 용어의 빈칸을 채우시오.

/* 데이터 관련 핵심 용어 */

┌───────────────┬──────────────────────────────────┐
│    용어        │            설명                   │
├───────────────┼──────────────────────────────────┤
│  (  ①  )      │ 정형·반정형·비정형 데이터를 원본   │
│               │ 그대로 저장하는 (  ②  ) 저장소     │
│               │ 스키마 없이 대규모 데이터 보관      │
├───────────────┼──────────────────────────────────┤
│  (  ③  )      │ 주제별로 통합·정제된 데이터를       │
│               │ 저장하는 (  ④  ) 중심 저장소       │
│               │ 의사결정 지원이 목적               │
├───────────────┼──────────────────────────────────┤
│  데이터마트    │ 데이터웨어하우스의 (  ⑤  )        │
│               │ 특정 부서·주제 영역의 데이터        │
├───────────────┼──────────────────────────────────┤
│  (  ⑥  )      │ Extract(추출), (  ⑦  )(변환),   │
│               │ Load(적재)의 약자                  │
│               │ 데이터 이관·정제 프로세스           │
├───────────────┼──────────────────────────────────┤
│  (  ⑧  )      │ 대량의 데이터에서 숨겨진 패턴·규칙 │
│               │ 을 자동으로 발견하는 기법           │
│               │ 기법: 분류, (  ⑨  ), 연관규칙 등  │
├───────────────┼──────────────────────────────────┤
│  (  ⑩  )      │ 데이터의 정의·구조·관계 등         │
│               │ '데이터에 대한 데이터'             │
└───────────────┴──────────────────────────────────┘
정답 및 해설 보기
① 데이터레이크(Data Lake) ② 대규모(중앙 집중식)
③ 데이터웨어하우스(Data Warehouse) ④ 주제(Subject) / 분석
⑤ 부분집합(서브셋/하위집합)
⑥ ETL ⑦ Transform
⑧ 데이터마이닝(Data Mining) ⑨ 군집화(Clustering)
⑩ 메타데이터(Metadata)
핵심: 데이터 저장·처리·분석 용어를 단계별로 이해하세요.
• 데이터레이크: 원본 데이터를 가공 없이 저장 → 나중에 필요할 때 분석 (Schema-on-Read)
• 데이터웨어하우스: 정제·변환된 구조화 데이터 저장 → 비즈니스 분석용 (Schema-on-Write)
• ETL: 원본 시스템에서 추출(E) → 형식 변환(T) → 타겟 시스템에 적재(L)
• 데이터마이닝: 분류(Classification), 군집화(Clustering), 연관규칙(Association), 예측 등
함정: 데이터레이크 vs 데이터웨어하우스 — 전자는 비정형 포함, 후자는 정형 데이터 중심!

앱 개발 방식 ★★★

시험 포인트: PWA의 핵심은 Service Worker(오프라인), SPA의 핵심은 클라이언트 사이드 렌더링!
