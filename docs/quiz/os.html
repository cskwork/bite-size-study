문제 1
프로세스 상태 전이 ★★★

다음 프로세스 상태 전이도의 빈칸을 채우시오.

/* 프로세스 상태 전이도 */

                  ┌─────────────┐
    (①)           │             │    (②)
 ──────→ [ New ] ──→ [ Ready ] ──→ [ Running ] ──→ [ Exit ]
                     ↑      │         │                (⑤)
                     │      │         │ (③)
                     │  (④) │         ↓
                     │      │    [ Waiting ]
                     │      │    (= Blocked)
                     └──────┘

상태 전이 이벤트:
① New → Ready:    (  ⑥  )
② Ready → Running: (  ⑦  )
③ Running → Waiting: (  ⑧  )
④ Waiting → Ready:  (  ⑨  )
⑤ Running → Ready:  (  ⑩  )
정답 및 해설 보기
① 생성(Admit) ② 디스패치(Dispatch) ③ I/O 요청 또는 이벤트 대기
④ I/O 완료 또는 이벤트 발생 ⑤ 종료(Exit/Terminate)
⑥ 프로세스 생성 후 준비 큐에 삽입 ⑦ 스케줄러가 CPU 할당 (디스패치)
⑧ I/O 요청, 자원 대기 등 ⑨ I/O 완료, 자원 가용 등
⑩ 타임아웃(Time-out) / 선점(Preemption)
핵심: 프로세스 5가지 상태와 전이 조건을 정확히 기억하세요.
• New: 프로세스 생성 중, PCB(Process Control Block) 생성
• Ready: CPU 할당을 기다리는 상태, 준비 큐에서 대기
• Running: CPU를 할당받아 실행 중인 상태
• Waiting(Blocked): I/O 완료 등 이벤트를 기다리는 상태
• Exit(Terminated): 실행 완료, 자원 반납, PCB 제거
⚠️ Running→Ready(선점)는 타임 슬라이스 만료 또는 높은 우선순위 프로세스 도착 시 발생합니다.
문제 2
CPU 스케줄링 계산 ★★★★

다음 프로세스들에 대해 SJF(Shortest Job First, 비선점) 스케줄링을 적용했을 때 평균 대기시간과 평균 반환시간을 구하시오.

/* CPU 스케줄링 - SJF (비선점) */

┌──────────┬──────────┬──────────┐
│ 프로세스   │ 도착시간  │ 실행시간  │
├──────────┼──────────┼──────────┤
│    P1    │    0     │    6     │
│    P2    │    1     │    8     │
│    P3    │    2     │    3     │
│    P4    │    3     │    4     │
└──────────┴──────────┴──────────┘

(1) 간트 차트를 그리시오: (  ①  )
(2) 각 프로세스의 대기시간: (  ②  )
(3) 평균 대기시간: (  ③  )
(4) 평균 반환시간(Turnaround Time): (  ④  )
정답 및 해설 보기
① |P1(0~6)|P3(6~9)|P4(9~13)|P2(13~21)|
② P1=0, P2=12, P3=4, P4=6
③ 평균 대기시간 = (0+12+4+6)/4 = 5.5
④ 평균 반환시간 = (6+20+7+10)/4 = 10.75
핵심: SJF 비선점은 실행 중인 프로세스가 끝날 때마다 대기 중 가장 짧은 프로세스를 선택합니다.
Step 1. 실행 순서 결정
t=0: P1만 도착 → P1 실행 (실행시간 6)
t=6: P1 완료, P2(8), P3(3), P4(4) 대기 중 → 최소 P3 선택
t=9: P3 완료, P2(8), P4(4) 대기 중 → 최소 P4 선택
t=13: P4 완료, P2(8) 대기 → P2 실행
Step 2. 간트 차트
|--P1--|--P3--|--P4--|----P2----|
0 6 9 13 21
Step 3. 대기시간 계산 (대기시간 = 시작시간 - 도착시간)
P1: 0 - 0 = 0
P2: 13 - 1 = 12
P3: 6 - 2 = 4
P4: 9 - 3 = 6
평균 = (0 + 12 + 4 + 6) / 4 = 5.5
Step 4. 반환시간 계산 (반환시간 = 완료시간 - 도착시간)
P1: 6 - 0 = 6
P2: 21 - 1 = 20
P3: 9 - 2 = 7
P4: 13 - 3 = 10
평균 = (6 + 20 + 7 + 10) / 4 = 10.75
⚠️ 비선점 vs 선점(SRTF): 비선점은 실행 중 교체 불가, 선점은 더 짧은 프로세스 도착 시 교체 가능!
문제 3
교착상태 ★★★

교착상태(Deadlock)의 발생 조건 4가지와 해결 방법을 쓰시오.

/* 교착상태 발생 조건 (4가지 모두 동시 충족 시 발생) */

(1) (  ①  ): 한 자원은 한 프로세스만 사용 가능
(2) (  ②  ): 자원을 보유한 채 다른 자원을 요청
(3) (  ③  ): 다른 프로세스가 보유한 자원을 강제로 빼앗을 수 없음
(4) (  ④  ): 프로세스 간 자원 요청이 원형으로 연결

/* 교착상태 해결 방법 */
(⑤): 교착상태가 발생하지 않도록 사전에 조건 부정
(⑥): 안전 상태를 유지하도록 자원 할당 (예: 은행원 알고리즘)
(⑦): 교착상태 발생 후 탐지하여 회복
(⑧): 교착상태를 무시 (발생 확률이 낮을 때)
정답 및 해설 보기
① 상호 배제 (Mutual Exclusion) ② 점유와 대기 (Hold and Wait)
③ 비선점 (Non-preemption) ④ 환형 대기 (Circular Wait)
⑤ 예방 (Prevention) ⑥ 회피 (Avoidance) ⑦ 탐지 및 회복 (Detection & Recovery)
⑧ 무시 (Ignore) - 타조 알고리즘
핵심: 4가지 조건이 모두 충족되어야 교착상태가 발생합니다. 하나라도 깨면 해결!
• 상호 배제: 공유 가능한 자원(읽기 전용 파일)은 교착상태 미발생
• 점유와 대기: 필요한 자원을 한꺼번에 요청하면 예방 가능
• 비선점: 자원을 선점 가능하게 하면 예방 가능 (실용적이지 않은 경우 多)
• 환형 대기: 자원에 번호를 부여하고 오름차순으로만 요청하면 예방 가능
• 은행원 알고리즘 (Banker's Algorithm): 안전 상태인지 확인 후 자원 할당 (회피 기법)
⚠️ "상점비환"으로 외우세요: 상호배제, 점유대기, 비선점, 환형대기. 시험 단골 문제입니다!
문제 4
페이지 교체 알고리즘 ★★★★

페이지 프레임이 3개일 때, 다음 페이지 참조열에 대해 FIFO와 LRU 알고리즘의 페이지 부재(Page Fault) 횟수를 구하시오.

/* 페이지 교체 알고리즘 - 프레임 3개 */

페이지 참조열: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3

/* (1) FIFO 알고리즘으로 풀이하시오 */
참조: 7  0  1  2  0  3  0  4  2  3
F1:  (                                )
F2:  (                                )
F3:  (                                )
부재: (                                )

FIFO 총 페이지 부재 횟수: (  ①  )

/* (2) LRU 알고리즘으로 풀이하시오 */
참조: 7  0  1  2  0  3  0  4  2  3
F1:  (                                )
F2:  (                                )
F3:  (                                )
부재: (                                )

LRU 총 페이지 부재 횟수: (  ②  )
정답 및 해설 보기
① FIFO: 9회 페이지 부재
② LRU: 9회 페이지 부재
핵심: FIFO는 가장 먼저 들어온 페이지를 교체, LRU는 가장 오랫동안 사용되지 않은 페이지를 교체
FIFO 풀이 (가장 먼저 들어온 것을 교체)
참조: 7   0   1   2   0   3   0   4   2   3
F1:  [7] [7] [7] [2] [2] [2] [0] [0] [0] [3]
F2:  [ ] [0] [0] [0] [0] [3] [3] [4] [4] [4]
F3:  [ ] [ ] [1] [1] [1] [1] [1] [1] [2] [2]
부재:  ●   ●   ●   ●       ●   ●   ●   ●   ●
t=0: 7 적재(F), t=1: 0 적재(F), t=2: 1 적재(F)
t=3: 2 → 7이 가장 오래됨 → 7 교체(F)
t=4: 0 → 이미 존재(Hit)
t=5: 3 → 0이 가장 오래됨 → 0 교체(F)
t=6: 0 → 1이 가장 오래됨 → 1 교체(F)
t=7: 4 → 2가 가장 오래됨 → 2 교체(F)
t=8: 2 → 3이 가장 오래됨 → 3 교체(F)
t=9: 3 → 0이 가장 오래됨 → 0 교체(F)
총 9회 페이지 부재
LRU 풀이 (가장 오래 사용 안 된 것을 교체)
참조: 7   0   1   2   0   3   0   4   2   3
F1:  [7] [7] [7] [2] [2] [2] [2] [4] [4] [3]
F2:  [ ] [0] [0] [0] [0] [0] [0] [0] [2] [2]
F3:  [ ] [ ] [1] [1] [1] [3] [3] [3] [3] [3] (수정)
부재:  ●   ●   ●   ●       ●   ●*  ●   ●   ●
t=3: 2 → 가장 오래 사용 안 된 7 교체(F)
t=4: 0 → Hit (0을 최근 사용으로 갱신)
t=5: 3 → 가장 오래 사용 안 된 1 교체(F)
t=6: 0 → Hit (이미 있음)
t=7: 4 → 가장 오래 사용 안 된 2 교체(F)
t=8: 2 → 가장 오래 사용 안 된 3... 등
총 9회 페이지 부재
⚠️ Belady's Anomaly: FIFO에서 프레임 수를 늘려도 페이지 부재가 증가할 수 있는 현상. LRU는 이 현상이 없습니다!
문제 5
디스크 스케줄링 ★★★

현재 헤드 위치가 50일 때, 다음 요청 큐에 대해 SSTF 디스크 스케줄링의 총 헤드 이동량을 구하시오.

/* 디스크 스케줄링 - SSTF */

현재 헤드 위치: 50
요청 큐: 82, 170, 43, 140, 24, 16, 190

/* 처리 순서와 이동량을 구하시오 */
처리 순서: (  ①  )
총 헤드 이동량: (  ②  )

/* 참고: 디스크 스케줄링 알고리즘 비교 */
(③): 요청 순서대로 처리 (공평하지만 비효율적)
(④): 현재 헤드에서 가장 가까운 요청 먼저 처리
(⑤): 한 방향으로 이동하며 처리 후 반대 방향으로
(⑥): 한 방향으로만 처리, 끝에서 처음으로 점프
정답 및 해설 보기
① 50→43→24→16→82→140→170→190
② 총 이동량 = 208
③ FCFS ④ SSTF ⑤ SCAN (엘리베이터) ⑥ C-SCAN
핵심: SSTF(Shortest Seek Time First)는 현재 위치에서 가장 가까운 트랙을 먼저 서비스합니다.
Step 1. 각 요청과의 거리 계산
현재=50: |82-50|=32, |170-50|=120, |43-50|=7, |140-50|=90, |24-50|=26, |16-50|=34, |190-50|=140
→ 가장 가까운: 43 (거리 7)
Step 2. 순서대로 처리
50→43: |50-43| = 7
43→24: |43-24| = 19
24→16: |24-16| = 8
16→82: |16-82| = 66
82→140: |82-140| = 58
140→170: |140-170| = 30
170→190: |170-190| = 20
Step 3. 총 이동량
7 + 19 + 8 + 66 + 58 + 30 + 20 = 208
⚠️ SSTF는 기아(Starvation) 문제 발생 가능 — 멀리 있는 요청이 계속 후순위로 밀릴 수 있습니다.
문제 6
메모리 관리 ★★★

다음 메모리 관리 기법의 빈칸을 채우시오.

/* 메모리 관리 기법 비교 */

┌──────────┬───────────────────┬───────────────────┐
│   구분    │     페이징         │   세그먼테이션      │
│          │    (Paging)       │  (Segmentation)    │
├──────────┼───────────────────┼───────────────────┤
│ 분할 단위 │   (  ①  )         │   (  ②  )         │
│ 크기     │   (  ③  )         │   (  ④  )         │
│ 단편화   │ (  ⑤  ) 단편화 발생 │ (  ⑥  ) 단편화 발생 │
│ 주소 변환 │ 페이지번호+오프셋   │   (  ⑦  )         │
│ 테이블   │   (  ⑧  )         │ 세그먼트 테이블     │
│ 장점     │ 외부 단편화 없음    │   (  ⑨  )         │
└──────────┴───────────────────┴───────────────────┘

/* 단편화 개념 */
(⑩) 단편화: 할당된 영역 내에서 사용하지 않는 공간
(⑪) 단편화: 할당되지 않은 작은 빈 공간들이 산재
정답 및 해설 보기
① 페이지 (Page) ② 세그먼트 (Segment)
③ 고정 크기 ④ 가변 크기
⑤ 내부(Internal) ⑥ 외부(External)
⑦ 세그먼트번호 + 오프셋 (변위)
⑧ 페이지 테이블 (Page Table)
⑨ 논리적 단위로 분할 (코드/데이터/스택 등 의미 있는 단위)
⑩ 내부(Internal) ⑪ 외부(External)
핵심: 페이징=고정크기→내부단편화, 세그먼테이션=가변크기→외부단편화
• 페이징: 프로세스를 동일 크기 페이지로 나누어 프레임에 적재 → 외부 단편화 해결
• 세그먼테이션: 논리적 단위(코드, 데이터, 스택)로 분할 → 공유/보호 용이
• 내부 단편화: 페이지 크기 4KB인데 실제 3KB만 사용 → 1KB 낭비
• 외부 단편화: 메모리에 빈 공간은 충분하지만 연속적이지 않아 할당 불가
• 페이지 테이블: 논리 주소의 페이지 번호 → 물리 주소의 프레임 번호 매핑
⚠️ 페이지드 세그먼테이션: 두 기법을 결합하여 세그먼트를 다시 페이지로 분할하는 방식도 있습니다.
문제 7
세마포어 · 뮤텍스 ★★★

다음 동기화 도구에 대한 빈칸을 채우시오.

/* 세마포어와 뮤텍스 비교 */

┌──────────┬───────────────────┬───────────────────┐
│   구분    │    세마포어         │     뮤텍스          │
│          │   (Semaphore)     │     (Mutex)        │
├──────────┼───────────────────┼───────────────────┤
│ 값 범위   │   (  ①  )         │   (  ②  )         │
│ 소유 개념 │   (  ③  )         │   (  ④  )         │
│ 연산     │   (  ⑤  )         │ Lock / Unlock     │
│ 용도     │ 동기화, 자원 카운팅  │   (  ⑥  )         │
└──────────┴───────────────────┴───────────────────┘

/* 세마포어 연산 (P/V 연산) */
P(S) 연산 (= (  ⑦  )):
  S = S - 1;
  if (S < 0) { // 프로세스를 대기 큐에 삽입 }

V(S) 연산 (= (  ⑧  )):
  S = S + 1;
  if (S <= 0) { // 대기 큐에서 프로세스 깨움 }

/* 임계영역 관련 조건 3가지 */
(⑨): 한 프로세스가 임계영역에 있으면 다른 프로세스 진입 불가
(⑩): 임계영역에 아무도 없으면 진입을 막으면 안 됨
(⑪): 유한 시간 내에 임계영역에 진입할 수 있어야 함
정답 및 해설 보기
① 0 이상의 정수 (카운팅) ② 0 또는 1 (이진)
③ 소유 개념 없음 ④ 소유 개념 있음 (잠근 스레드만 해제 가능)
⑤ P(Wait) / V(Signal) ⑥ 상호 배제 (Mutual Exclusion)
⑦ Wait (대기) ⑧ Signal (신호)
⑨ 상호 배제 (Mutual Exclusion) ⑩ 진행 (Progress) ⑪ 한정 대기 (Bounded Waiting)
핵심: 세마포어는 카운팅 가능, 뮤텍스는 이진(0/1)으로 상호배제 전용
• 이진 세마포어: 값이 0 또는 1 → 뮤텍스와 유사하지만 소유 개념 차이
• 카운팅 세마포어: 값이 N → N개의 자원을 관리 (예: 동시 접속 수 제한)
• P 연산 (Wait/Down): 자원 사용 요청, S를 1 감소
• V 연산 (Signal/Up): 자원 반납, S를 1 증가
• 뮤텍스 소유: Lock을 건 스레드만 Unlock 가능 (세마포어는 다른 프로세스가 V 연산 가능)
⚠️ P/V 연산은 네덜란드어: P=Proberen(시도), V=Verhogen(증가). 시험에서 P/V 코드 해석 문제 출제!

파일 시스템 ★★

다음 파일 시스템에 대한 설명의 빈칸을 채우시오.

/* 파일 시스템 비교 */

┌──────────┬──────────────┬──────────────┬──────────────┐
│   구분    │    FAT32     │    NTFS      │    ext4      │

│ 보안(ACL)│  미지원      │  (  ⑥  )     │   지원       │

/* Unix/Linux inode */
(⑧): 파일의 메타데이터를 저장하는 자료구조
  - 저장 내용: (  ⑨  )
  - 저장하지 않는 것: (  ⑩  )
정답 및 해설 보기
① Windows, DOS (범용) ② Windows ③ Linux
④ 4GB ⑤ 미지원 ⑥ 지원 (Access Control List)

⑧ inode (Index Node)
⑨ 파일 크기, 소유자, 권한, 타임스탬프, 데이터 블록 포인터 등
⑩ 파일 이름 (파일 이름은 디렉토리 엔트리에 저장)
핵심: 각 파일 시스템의 특징과 제한사항을 비교하세요.
• FAT32: 단순 구조, 범용 호환성, 4GB 파일 크기 제한이 최대 단점
• NTFS: 저널링, ACL 보안, 암호화(EFS), 압축, 대용량 지원
• ext4: Linux 표준, 저널링, 대용량 지원, 지연 할당으로 성능 향상
• inode: Unix/Linux에서 파일마다 고유한 번호(inode number) 부여, 파일 이름은 포함하지 않음
• 저널링: 변경사항을 로그에 먼저 기록 → 시스템 장애 시 복구 가능

문제 9
리눅스 명령어 ★★★

다음 유닉스/리눅스 명령어의 실행 결과 또는 기능을 쓰시오.

/* 리눅스 명령어 문제 */

(1) 파일 권한이 rwxr-x--- 일 때 8진수 표현: (  ①  )

(2) 다음 명령어의 의미:
    chmod 754 file.txt  →  (  ②  )

(3) chmod의 기호 모드:
    chmod u+x,g-w,o=r file.txt
    → 소유자에게 (  ③  ) 권한 추가
    → 그룹에서 (  ④  ) 권한 제거
    → 기타 사용자에 (  ⑤  ) 권한만 설정

(4) 프로세스 관련 명령어:
    ps -ef        →  (  ⑥  )
    kill -9 1234  →  (  ⑦  )

(5) 텍스트 검색 명령어:
    grep -r "error" /var/log/  →  (  ⑧  )

(6) 파이프와 리다이렉션:
    cat file.txt | grep "hello" | wc -l  →  (  ⑨  )

(7) 기타 명령어:
    crontab -e  →  (  ⑩  )
정답 및 해설 보기
① 750
② 소유자(rwx=7), 그룹(r-x=5), 기타(r--=4) 권한 설정
③ 실행(x) ④ 쓰기(w) ⑤ 읽기(r)
⑥ 모든 프로세스를 상세 정보와 함께 출력
⑦ PID 1234 프로세스를 강제 종료 (SIGKILL)
⑧ /var/log/ 디렉토리에서 재귀적으로 "error" 문자열 검색
⑨ file.txt에서 "hello"가 포함된 줄의 수를 출력
⑩ 크론탭(예약 작업) 편집
핵심: 권한 8진수 변환과 주요 명령어 옵션을 외우세요.
chmod 권한 계산:
r(읽기)=4, w(쓰기)=2, x(실행)=1
rwx = 4+2+1 = 7
r-x = 4+0+1 = 5
--- = 0+0+0 = 0
→ rwxr-x--- = 750
• kill 시그널: -9(SIGKILL 강제종료), -15(SIGTERM 정상종료), -2(SIGINT=Ctrl+C)
• ps 옵션: -e(모든 프로세스), -f(상세정보), -aux(BSD 형식)
• grep 옵션: -r(재귀), -i(대소문자 무시), -n(줄번호), -c(매칭 수)
• 파이프(|): 앞 명령의 출력을 뒤 명령의 입력으로 전달
⚠️ chmod 755, 644, 750 등 자주 쓰이는 권한 조합은 반드시 외우세요. 시험 단골!
문제 10
가상메모리 · 스래싱 ★★★

다음 가상메모리 관련 개념의 빈칸을 채우시오.

/* 가상메모리 핵심 개념 */

(1) (  ①  ): 실제 물리 메모리보다 큰 주소 공간을
    사용할 수 있게 하는 메모리 관리 기법

(2) (  ②  ): 프로세스가 실행 중 특정 시간 동안
    자주 참조하는 페이지들의 집합

(3) (  ③  ): 다중 프로그래밍의 정도가 높아져
    페이지 부재가 급증하고 CPU 이용률이
    급격히 떨어지는 현상

/* 스래싱 관련 그래프 */

  CPU     ┃        ╱╲
  이용률   ┃      ╱    ╲
          ┃    ╱        ╲  ← (③) 발생
          ┃  ╱            ╲
          ┃╱                ╲___
          ┗━━━━━━━━━━━━━━━━━━━━━
           다중 프로그래밍 정도 →

(4) 스래싱 예방 방법:
    - (  ④  ) 모델 사용
    - (  ⑤  ) 제어
    - 프로세스 수 조절

(5) (  ⑥  ): 프로세스 실행 시 필요한 페이지만
    메모리에 적재하는 기법

(6) 페이지 부재율(Page Fault Rate):
    상한선 초과 → (  ⑦  )
    하한선 미만 → (  ⑧  )
정답 및 해설 보기
① 가상 메모리 (Virtual Memory)
② 워킹셋 (Working Set)
③ 스래싱 (Thrashing)
④ 워킹셋 (Working Set) ⑤ 페이지 부재 빈도 (PFF, Page Fault Frequency)
⑥ 요구 페이징 (Demand Paging)
⑦ 프레임 추가 할당 ⑧ 프레임 회수
핵심: 스래싱은 페이지 부재가 과다하여 실제 작업보다 페이지 교체에 더 많은 시간을 소비하는 현상
• 워킹셋: 시간 윈도우 Δ 동안 참조된 페이지 집합 → 이만큼의 프레임을 보장해야 함
• 스래싱 원인: 프레임 부족 → 페이지 부재 빈발 → I/O 급증 → CPU 유휴 → OS가 프로세스 추가 → 악순환
• PFF (Page Fault Frequency): 페이지 부재율의 상한/하한을 설정하여 프레임 수를 동적 조절
• 요구 페이징: 실행에 필요한 페이지만 메모리에 올림 → 초기 적재 시간 단축
• 선반입(Prepaging): 필요할 것으로 예상되는 페이지를 미리 적재
• 지역성(Locality): 시간적 지역성(최근 참조 페이지 재참조), 공간적 지역성(인접 페이지 참조)
⚠️ 워킹셋 크기 = 시간 윈도우 Δ 내의 고유 페이지 수. 스래싱 방지의 핵심 개념입니다!
