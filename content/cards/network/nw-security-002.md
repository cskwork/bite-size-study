## 암호화 방식 — 대칭키 vs 비대칭키 vs 해시

### 핵심 개념
암호화는 데이터의 기밀성과 무결성을 보장하는 핵심 기술이다. 대칭키 암호화는 하나의 키로 암·복호화하고, 비대칭키 암호화는 공개키와 개인키 쌍을 사용한다. 해시 함수는 단방향 변환으로 원본 복원이 불가능하며 무결성 검증에 사용된다.

### 키워드
- **대칭키 암호화**: 암호화·복호화에 동일한 키 사용. 속도 빠름. 키 배포 문제 존재. **DES**(56비트, 현재 취약), **3DES**(DES 3회 적용), **AES**(128/192/256비트, 현재 표준), **SEED**(한국 표준, 128비트), **ARIA**(한국 표준)
- **비대칭키 암호화**: 공개키(암호화)와 개인키(복호화)를 분리 사용. 키 배포 문제 해결. 속도 느림. **RSA**(소인수분해 기반), **ECC**(타원곡선), **ElGamal**(이산대수), **DSA**(디지털 서명)
- **해시 함수**: 임의 길이 입력 → 고정 길이 출력. 단방향(복호화 불가). 무결성 검증, 비밀번호 저장. **SHA-256**(256비트), **MD5**(128비트, 취약), **SHA-1**(160비트, 취약)
- **하이브리드 암호**: 실제 통신에서는 대칭키+비대칭키를 결합. 비대칭키로 대칭키를 교환한 뒤, 대칭키로 데이터 암호화 (예: TLS/SSL)
- **전자서명**: 개인키로 서명 → 공개키로 검증. 부인 방지(Non-repudiation)와 무결성 보장

### 기출 포인트
> 대칭키·비대칭키·해시의 특성 비교표 문제가 빈출된다. **AES**와 **RSA**의 분류(대칭/비대칭)를 묻는 문제, **해시 함수의 단방향성** 특성을 서술하는 문제가 자주 출제된다. 한국 표준 암호 알고리즘인 **SEED**, **ARIA**도 출제 범위에 포함된다. 전자서명에서 **개인키로 서명·공개키로 검증**하는 순서를 헷갈리지 않도록 주의해야 한다.
