## 인덱스 (B-Tree, Hash, Bitmap) — 구조와 사용 시점

### 핵심 개념
인덱스(Index)는 테이블의 검색 속도를 향상시키기 위해 별도로 생성하는 **데이터 구조**이다. 인덱스는 책의 목차와 같은 역할로, 전체 테이블을 스캔(Full Table Scan)하지 않고 원하는 데이터의 물리적 위치를 빠르게 찾을 수 있게 한다. 단, 인덱스는 추가 저장 공간을 차지하고 INSERT/UPDATE/DELETE 시 인덱스도 갱신해야 하므로 **쓰기 성능이 저하**될 수 있다.

### 키워드
- **B-Tree 인덱스**: 균형 트리 구조로 **범위 검색과 동등 검색 모두** 효율적. 대부분의 DBMS 기본 인덱스. 루트→브랜치→리프 노드로 구성되며 O(log N) 탐색
- **Hash 인덱스**: 해시 함수를 사용하여 **동등 비교(=)에 O(1)** 성능. 범위 검색(>, <, BETWEEN)에는 사용 불가. 메모리 기반 테이블에 주로 사용
- **Bitmap 인덱스**: 각 값에 대해 비트맵(0/1 배열)을 생성. **카디널리티가 낮은**(값의 종류가 적은) 컬럼에 적합. 예: 성별(M/F), 상태(활성/비활성). OLAP 환경에 유리
- **클러스터드 인덱스**: 테이블당 1개만 존재. 데이터가 인덱스 순서대로 **물리적 정렬**됨. PK에 자동 생성
- **넌클러스터드 인덱스**: 테이블당 여러 개 가능. 별도의 인덱스 페이지에 논리적 포인터 저장

### 기출 포인트
> B-Tree = 범위+동등, Hash = 동등만, Bitmap = 낮은 카디널리티 — 이 세 가지 특성 비교가 핵심이다. 인덱스를 생성하면 SELECT 성능은 향상되지만 INSERT/UPDATE/DELETE 성능은 저하된다는 **트레이드오프**도 빈출 포인트다. 클러스터드 인덱스는 "테이블당 1개, 물리적 정렬"이라는 점을 기억할 것.
