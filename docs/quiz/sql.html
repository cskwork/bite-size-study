Q2
GROUP BY / HAVING / 집계함수 ★★★

다음 테이블과 SQL문의 실행 결과를 쓰시오.

▼ 성적(SCORE) 테이블
STUDENTSUBJECTPOINT
홍길동국어85
홍길동영어90
홍길동수학75
이순신국어95
이순신영어80
강감찬국어70
강감찬영어65
SELECT STUDENT, AVG(POINT) AS AVG_POINT
FROM SCORE
GROUP BY STUDENT
HAVING AVG(POINT) >= 80
ORDER BY AVG_POINT DESC;
답 / 해설 보기
이순신 87.5 홍길동 83.3...
풀이:
1. GROUP BY STUDENT → 학생별 그룹화
2. AVG 계산: 홍길동=(85+90+75)/3≈83.3, 이순신=(95+80)/2=87.5, 강감찬=(70+65)/2=67.5
3. HAVING AVG(POINT) >= 80 → 강감찬(67.5) 제외
4. ORDER BY AVG_POINT DESC → 이순신(87.5), 홍길동(83.3)
AVG 결과의 소수점 표현은 DBMS에 따라 다를 수 있음 (반올림/절삭 차이 주의)

JOIN (INNER, LEFT) ★★★★

다음 두 테이블과 SQL문의 실행 결과를 쓰시오.

SELECT S.SNAME, E.COURSE
FROM STUDENT S LEFT JOIN ENROLL E
ON S.SID = E.SID
ORDER BY S.SNAME;
답 / 해설 보기
김철수 DB 김철수 OS 박민수 NULL 이영희 DB
풀이:
1. LEFT JOIN → 왼쪽 테이블(STUDENT)의 모든 행이 결과에 포함
2. 김철수(SID=1) → DB, OS 두 과목 수강
3. 이영희(SID=2) → DB 한 과목 수강
4. 박민수(SID=3) → 수강 내역 없음 → COURSE가 NULL
5. ORDER BY SNAME → 가나다순 정렬
INNER JOIN이었다면 박민수는 결과에 포함되지 않음

서브쿼리 (IN, EXISTS) ★★★★

다음 테이블과 SQL문의 실행 결과를 쓰시오.

▼ 부서(DEPT) 테이블
DNODNAMELOC
10개발서울
20인사부산
30영업대전
▼ 사원(EMP) 테이블
ENAMEDNOSALARY
김철수103500

박민수203000

SELECT ENAME, SALARY
FROM EMP
WHERE DNO IN (SELECT DNO FROM DEPT WHERE LOC = '서울')
  AND SALARY > ALL (SELECT SALARY FROM EMP WHERE DNO = 20);
답 / 해설 보기
김철수 3500 이영희 4200
풀이:
1. 서브쿼리1: SELECT DNO FROM DEPT WHERE LOC='서울' → DNO = 10
2. 서브쿼리2: SELECT SALARY FROM EMP WHERE DNO=20 → 3000
3. > ALL (3000) → 3000보다 큰 모든 값 → SALARY > 3000
4. DNO=10이면서 SALARY > 3000 → 김철수(3500), 이영희(4200)
ALL은 서브쿼리 결과의 모든 값보다 커야 함. ANY(=SOME)는 하나라도 만족하면 됨
Q5
CREATE TABLE / 제약조건 ★★★

다음 조건을 만족하는 SQL문의 빈칸 ①~④를 채우시오.

• 학번(SNO)은 기본키
• 이름(SNAME)은 NULL 불가
• 학과번호(DNO)는 학과 테이블의 DNO를 참조하는 외래키
• 나이(AGE)는 18 이상 

CREATE TABLE 학생 (
    SNO    INT         ①,
    SNAME  VARCHAR(20) ②,
    DNO    INT         ③,
    AGE    INT         ④
);
답 / 해설 보기
① PRIMARY KEY ② NOT NULL ③ REFERENCES 학과(DNO) 또는 FOREIGN KEY REFERENCES 학과(DNO) ④ CHECK(AGE >= 18)
풀이:
① PRIMARY KEY — 기본키 제약조건 (자동으로 NOT NULL + UNIQUE 포함)
② NOT NULL — NULL 값 입력 불가 제약조건
③ REFERENCES 학과(DNO) — 외래키 제약조건, 참조 테이블과 컬럼 명시
④ CHECK(AGE >= 18) — 도메인 제약조건, 18 이상의 값만 허용
FOREIGN KEY는 컬럼 레벨에서 REFERENCES만 쓰거나, 테이블 레벨에서 FOREIGN KEY(DNO) REFERENCES 학과(DNO) 형태도 가능
Q6
INSERT / UPDATE / DELETE ★★

다음 SQL문들을 순서대로 실행한 후 테이블의 최종 상태를 쓰시오.

▼ 제품(PRODUCT) 초기 상태
PIDPNAMEPRICE
1키보드50000
2마우스30000
3모니터250000
INSERT INTO PRODUCT VALUES (4, '스피커', 80000);
UPDATE PRODUCT SET PRICE = PRICE * 1.1 WHERE PRICE < 100000;
DELETE FROM PRODUCT WHERE PNAME = '모니터';
답 / 해설 보기
PID PNAME PRICE 1 키보드 55000 2 마우스 33000 4 스피커 88000
풀이:
1. INSERT → (4, 스피커, 80000) 추가
2. UPDATE → PRICE < 100000인 행(키보드50000, 마우스30000, 스피커80000)에 1.1배 적용 → 55000, 33000, 88000
3. DELETE → PNAME='모니터' 행 삭제 (모니터 250000은 UPDATE 조건에 해당 안 됨, 그대로 250000이었다가 삭제)
UPDATE의 WHERE 조건은 UPDATE 실행 시점의 값을 기준으로 판단함

VIEW 생성과 활용 ★★★

다음 SQL문의 빈칸 ①, ②를 채우시오.

▼ 사원(EMP) 테이블
EMPNONAMEDEPTSALARY
101김철수개발3500
102이영희인사3000
103박민수개발4000
104최지연영업2800
-- 개발부서 사원만 보여주는 뷰 생성
① VIEW DEV_EMP AS
SELECT EMPNO, NAME, SALARY
FROM EMP
WHERE DEPT = '개발';

-- 뷰 삭제
② VIEW DEV_EMP;
답 / 해설 보기
① CREATE (또는 CREATE OR REPLACE) ② DROP
풀이:
① CREATE VIEW — 뷰를 생성하는 DDL. 이미 존재할 경우를 대비해 CREATE OR REPLACE VIEW도 가능
② DROP VIEW — 뷰를 삭제하는 DDL
뷰 조회: SELECT * FROM DEV_EMP; → 김철수(3500), 박민수(4000) 출력
뷰는 논리적 테이블로 실제 데이터를 저장하지 않음. 원본 테이블 데이터가 변경되면 뷰 결과도 변경됨
Q8
권한관리 GRANT / REVOKE ★★★

다음 설명에 맞는 SQL문의 빈칸 ①~④를 채우시오.

-- 사용자 'hong'에게 EMP 테이블에 대한
-- SELECT, INSERT 권한을 부여하고,
-- hong이 다른 사용자에게 권한을 부여할 수 있도록 허용
① ② ON EMP TO hong ③;

-- 사용자 'hong'으로부터 INSERT 권한을 회수하되,
-- hong이 다른 사용자에게 부여한 INSERT 권한도 함께 회수
④ INSERT ON EMP FROM hong CASCADE;
답 / 해설 보기
① GRANT ② SELECT, INSERT ③ WITH GRANT OPTION ④ REVOKE
풀이:
① GRANT — 권한 부여 DCL 명령어
② SELECT, INSERT — 부여할 권한 목록
③ WITH GRANT OPTION — 부여받은 권한을 다른 사용자에게도 부여할 수 있는 옵션
④ REVOKE — 권한 회수 DCL 명령어
CASCADE는 연쇄적으로 권한을 회수. RESTRICT는 다른 사용자에게 부여된 권한이 있으면 회수 거부

윈도우 함수 (RANK, ROW_NUMBER) ★★★★

다음 테이블과 SQL문의 실행 결과를 쓰시오.

▼ 성적(RESULT) 테이블
NAMECLASSSCORE
김철수A95
이영희A90
박민수A90
최지연B85
정수현B100
SELECT NAME, CLASS, SCORE,
       RANK() OVER (PARTITION BY CLASS ORDER BY SCORE DESC) AS RK,
       ROW_NUMBER() OVER (PARTITION BY CLASS ORDER BY SCORE DESC) AS RN
FROM RESULT;
답 / 해설 보기
김철수 A 95 1 1 이영희 A 90 2 2 박민수 A 90 2 3 정수현 B 100 1 1 최지연 B 85 2 2
풀이:
1. PARTITION BY CLASS → 반(A, B)별로 분리하여 순위 산출
2. A반: 김철수(95)→1위, 이영희/박민수(90)→공동 2위
3. RANK() → 동일 점수는 같은 순위, 다음 순위 건너뜀 (1, 2, 2, 4…)
4. ROW_NUMBER() → 동일 점수라도 고유 번호 부여 (1, 2, 3…)
5. B반: 정수현(100)→1위, 최지연(85)→2위
DENSE_RANK()는 동일 순위 후 다음 순위를 건너뛰지 않음 (1, 2, 2, 3…)
Q10
트랜잭션 (COMMIT, ROLLBACK, SAVEPOINT) ★★★

다음 SQL문을 순서대로 실행한 후, 테이블에 남아 있는 행을 쓰시오.

▼ 상품(ITEM) 초기 상태 (비어 있음)
INSERT INTO ITEM VALUES (1, '사과');
SAVEPOINT S1;

INSERT INTO ITEM VALUES (2, '바나나');
SAVEPOINT S2;

INSERT INTO ITEM VALUES (3, '포도');
ROLLBACK TO S2;

INSERT INTO ITEM VALUES (4, '딸기');
ROLLBACK TO S1;

INSERT INTO ITEM VALUES (5, '수박');
COMMIT;
답 / 해설 보기
1 사과 5 수박
풀이:
1. INSERT (1, 사과) → 테이블: {사과}
2. SAVEPOINT S1 → 사과까지 저장점
3. INSERT (2, 바나나) → 테이블: {사과, 바나나}
4. SAVEPOINT S2 → 바나나까지 저장점
5. INSERT (3, 포도) → 테이블: {사과, 바나나, 포도}
6. ROLLBACK TO S2 → 포도 취소 → 테이블: {사과, 바나나}
7. INSERT (4, 딸기) → 테이블: {사과, 바나나, 딸기}
8. ROLLBACK TO S1 → 바나나, 딸기 모두 취소 → 테이블: {사과}
9. INSERT (5, 수박) → 테이블: {사과, 수박}
10. COMMIT → 최종 확정: {사과, 수박}
ROLLBACK TO는 해당 SAVEPOINT 이후의 모든 작업을 취소함. SAVEPOINT 이전의 작업은 유지됨
