## 접근 통제 모델 (MAC, DAC, RBAC) & 인증 기술 (OAuth, OTP)

### 핵심 개념
접근 통제는 인가된 사용자만 자원에 접근하도록 제한하는 보안 메커니즘이다. MAC은 시스템이 강제로 통제(군사/정부), DAC는 자원 소유자가 자율 결정(일반 OS), RBAC는 역할에 따라 권한 부여(기업 환경)로 구분된다. OAuth는 제3자 위임 인증, OTP는 일회용 비밀번호로 인증 강화에 사용된다.

### 키워드

**MAC (Mandatory Access Control, 강제적 접근 통제)**
- **주체**: 시스템/관리자 (사용자가 변경 불가)
- **기준**: 정보의 보안 등급(비밀, 극비 등) + 사용자의 허가 등급 비교
- **특징**: 가장 엄격, 사용자가 임의로 권한 변경 불가
- **적용**: 군사 기관, 정부 기밀 시스템

**DAC (Discretionary Access Control, 임의적 접근 통제)**
- **주체**: 자원 소유자 (파일 주인이 권한 결정)
- **기준**: 소유자의 재량 (ACL 기반)
- **특징**: 유연하나 허가 전파(Permission Leakage) 위험
- **적용**: 일반 Unix/Windows 파일 시스템

**RBAC (Role-Based Access Control, 역할 기반 접근 통제)**
- **주체**: 역할(Role)에 권한 부여 → 사용자는 역할 할당
- **기준**: 사용자의 직무/역할 (관리자, 개발자, 뷰어 등)
- **특징**: 관리 편의성, 최소 권한 원칙 실현 용이
- **적용**: 기업 내부 시스템, 클라우드 IAM

**OAuth (Open Authorization)**
- **역할**: 제3자 애플리케이션에 자원 접근 권한을 위임하는 표준 프로토콜
- **흐름**: 사용자 → 클라이언트 앱 → 인가 서버(구글/카카오) → Access Token 발급 → 자원 접근
- **핵심**: 비밀번호를 직접 공유하지 않고 토큰으로 위임
- **버전**: OAuth 2.0이 현행 표준

**OTP (One-Time Password, 일회용 비밀번호)**
- **역할**: 매번 다른 비밀번호 생성 → 재사용 불가, 캡처 공격 방어
- **종류**: TOTP(시간 기반), HOTP(카운터 기반)
- **활용**: 2단계 인증(2FA), 은행 OTP 카드/앱

### 비교 요약

| 모델 | 통제 주체 | 핵심 기준 | 유연성 |
|------|---------|---------|-------|
| MAC | 시스템 | 보안 등급 | 낮음 (엄격) |
| DAC | 소유자 | 자율 재량 | 높음 (유연) |
| RBAC | 관리자 | 역할(직무) | 중간 |

### 기출 포인트
> **2025-3회**: MAC/DAC/RBAC 세 모델 비교 + OAuth, OTP 개념 한 문제에 복합 출제
> **MAC 구분 포인트**: "사용자가 임의 변경 불가" = 강제(Mandatory) = MAC
> **DAC 구분 포인트**: "소유자가 결정" = 임의(Discretionary) = DAC
> **OAuth 핵심**: "비밀번호 없이 권한 위임" → 카카오 로그인, 구글 소셜 로그인 사례
> **OTP 핵심**: "매번 다른 비밀번호" → 재사용 불가, 피싱/스니핑 방어
