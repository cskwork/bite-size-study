## 오류 검출과 수정 (패리티, CRC, 해밍코드, FEC, BEC)

### 핵심 개념
데이터 전송 과정에서 발생하는 오류를 처리하는 방식은 크게 **FEC(전진오류수정)**과 **BEC(후진오류수정)**으로 나뉜다. FEC는 수신 측에서 오류를 자체 수정하는 방식이고, BEC는 오류를 검출 후 재전송을 요청하는 방식이다. 패리티 비트는 가장 단순한 오류 검출 기법이며, CRC는 다항식 연산으로 강력한 오류 검출을 제공하고, 해밍코드는 오류를 자동 수정할 수 있다.

### 키워드

#### 오류 제어 방식 분류

| 방식 | 방법 | 특징 |
|-----|------|------|
| **FEC(Forward Error Correction)** | 수신 측에서 오류 자동 수정 | 재전송 불필요, 해밍코드 등 사용, 역방향 채널 불필요 |
| **BEC(Backward Error Correction)** | 오류 검출 후 재전송 요청 | ARQ(Automatic Repeat reQuest), 역방향 채널 필요 |

#### 패리티 비트(Parity Bit)
- **짝수 패리티(Even Parity)**: 데이터 비트 중 1의 개수가 짝수가 되도록 패리티 비트 추가
- **홀수 패리티(Odd Parity)**: 데이터 비트 중 1의 개수가 홀수가 되도록 패리티 비트 추가
- **1비트 오류만 검출 가능**, 수정 불가
- 2비트 오류는 검출 불가 (짝수 오류 무시)

#### CRC(Cyclic Redundancy Check)
- 생성 다항식으로 나누어 나머지(CRC 코드) 계산 후 프레임 끝에 첨부
- 수신 측에서 동일한 다항식으로 나누어 나머지가 0이면 정상
- 버스트 오류 검출에 강력 (연속된 여러 비트 오류)
- 대표 표준: CRC-16, CRC-32 (이더넷, ZIP 등에서 사용)
- **오류 검출만 가능**, 수정 불가

#### 해밍코드(Hamming Code)
- 데이터 비트 사이에 **패리티 비트를 삽입**하여 오류 위치 특정
- 오류 **검출과 자동 수정** 모두 가능 (1비트 오류 수정, 2비트 오류 검출)
- 패리티 비트 위치: 2의 거듭제곱 위치 (1, 2, 4, 8, ...)
- 데이터 비트 수가 d이면, 2^p ≥ d + p + 1을 만족하는 최소 p개의 패리티 비트 필요

#### ARQ 방식 (BEC의 구현)
- **Stop-and-Wait ARQ**: 프레임 전송 후 ACK 수신까지 대기 — 단순하나 효율 낮음
- **Go-Back-N ARQ**: 오류 프레임부터 모두 재전송
- **Selective Repeat ARQ**: 오류 프레임만 선택적 재전송 — 효율 높음

### 기출 포인트
> **2025-1회**: CRC 생성 다항식을 이용한 CRC 코드 계산 과정과 오류 검출 원리 서술 문제 출제.
> **2025-3회**: FEC/BEC 차이, 해밍코드의 패리티 비트 위치 계산, 패리티/CRC 비교 종합 문제 출제.
> FEC vs BEC는 "수신 측 자체 수정" vs "재전송 요청"으로 한 줄로 구분 가능.
> 해밍코드에서 **패리티 비트 개수 계산 공식** (2^p ≥ d+p+1)은 암기 필수.
> 패리티는 홀수 개 비트 오류만 검출, CRC는 버스트 오류에 강함이 비교 핵심.
