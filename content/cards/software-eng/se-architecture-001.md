## 소프트웨어 아키텍처 패턴

### 핵심 개념
소프트웨어 아키텍처 패턴은 시스템의 전체적인 구조를 정의하는 검증된 설계 방식이다. 각 패턴은 특정 문제 상황에 적합하며, 시스템의 품질 속성(성능, 유지보수성, 확장성 등)에 직접적인 영향을 미친다. 정보처리기사에서는 대표적인 4가지 패턴의 특징과 적용 상황을 구분할 수 있어야 한다.

### 키워드
- **레이어드 패턴(Layered)**: 시스템을 계층으로 분리 (예: 표현-비즈니스-데이터). 각 계층은 인접 계층과만 통신. 변경 영향 최소화
- **클라이언트-서버 패턴**: 서비스를 제공하는 서버와 요청하는 클라이언트로 분리. 서버는 자원을 중앙 관리
- **파이프-필터 패턴(Pipe-Filter)**: 데이터 스트림을 독립적인 필터가 순차 처리. 각 필터는 입력을 가공하여 출력. UNIX 명령어 파이프라인이 대표적 예시
- **MVC 패턴**: Model(데이터/로직), View(화면 표시), Controller(입력 처리)로 분리. 사용자 인터페이스와 비즈니스 로직의 독립적 개발 가능
- **마스터-슬레이브 패턴**: 마스터가 작업을 분배하고 슬레이브가 실행 후 결과를 반환. 병렬 처리에 적합

### 기출 포인트
> 아키텍처 패턴 문제는 패턴 이름과 설명을 매칭하는 형태가 주로 출제된다. 특히 **파이프-필터**와 **레이어드**의 차이점(데이터 흐름 처리 vs 계층 간 책임 분리), **MVC**에서 각 구성요소(Model, View, Controller)의 역할을 정확히 구분해야 한다. 추가로 **브로커 패턴**(분산 시스템에서 컴포넌트 간 통신 조정)과 **이벤트 버스 패턴**도 출제 범위에 포함된다.
