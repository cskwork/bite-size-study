문제 1
개발 방법론 ★★★

다음 설명에 해당하는 소프트웨어 개발 방법론의 이름을 각각 쓰시오.

(1) 각 단계를 확실히 매듭짓고 다음 단계로 넘어가는 선형 순차적 모델로, 요구사항 변경이 어렵다는 단점이 있다.
(2) 계획수립 → 위험분석 → 개발 → 고객평가를 반복하며, 위험 관리를 핵심으로 하는 모델이다.
(3) 고객과의 협력, 변화 대응, 동작하는 소프트웨어를 중시하며 반복·점진적으로 개발하는 방법론이다.
(4) 자료 흐름도(DFD), 자료 사전(DD), 소단위 명세서 등을 활용하여 기능 중심으로 분석하는 방법론이다.

정답 및 해설 보기
(1) 폭포수(Waterfall) 모델
(2) 나선형(Spiral) 모델
(3) 애자일(Agile) 방법론
(4) 구조적(Structured) 방법론
핵심: 4대 개발 방법론의 특징을 구분하는 문제
• 폭포수: 요구분석→설계→구현→테스트→유지보수 순차 진행. 단계 회귀 어려움
• 나선형: Boehm 제안. 대규모 시스템에 적합. 위험분석 단계가 특징
• 애자일: 2001년 애자일 선언문(Agile Manifesto) 기반. XP, 스크럼 등 포함
• 구조적: 기능 분해, 하향식(Top-Down) 접근. DFD, DD, Mini-Spec 활용

(4) 변경 조건/결정(MC/DC) 커버리지 100%를 위한 최소 테스트 케이스 수: (   )개

정답 및 해설 보기
(1) 1개   (2) 2개   (3) 2개   (4) 3개

결합도(Coupling) ★★★

모듈 간 결합도(Coupling)를 낮은 것부터 높은 순서로 나열할 때, 괄호를 채우시오.

( ① ) → ( ② ) → ( ③ ) → ( ④ ) → ( ⑤ ) → ( ⑥ ) → ( ⑦ )

보기: 자료 결합도, 스탬프 결합도, 제어 결합도, 외부 결합도, 공통 결합도, 내용 결합도, 자료구조 결합도

※ 결합도가 낮을수록 좋은 설계이다.

정답 및 해설 보기
① 자료(Data) → ② 스탬프(Stamp) → ③ 제어(Control) → ④ 외부(External) → ⑤ 공통(Common) → ⑥ 내용(Content)
핵심: 결합도 암기법 — "자스제외공내" (자료→스탬프→제어→외부→공통→내용)
• 자료 결합도: 매개변수로 단순 데이터만 전달 (가장 낮음 = 가장 좋음)
• 스탬프 결합도: 자료구조(배열, 레코드)를 통째로 전달
• 제어 결합도: 제어 요소(플래그, 스위치)를 전달하여 내부 논리 제어
• 외부 결합도: 외부에서 선언된 데이터(변수)를 공유
• 공통 결합도: 전역 변수(공통 데이터 영역)를 공유
• 내용 결합도: 다른 모듈의 내부를 직접 참조/수정 (가장 높음 = 가장 나쁨)
문제 6
응집도(Cohesion) ★★★

모듈 내 응집도(Cohesion)를 높은 것부터 낮은 순서로 나열할 때, 괄호를 채우시오.

( ① ) → ( ② ) → ( ③ ) → ( ④ ) → ( ⑤ ) → ( ⑥ ) → ( ⑦ )

보기: 기능적, 순차적, 교환적, 절차적, 시간적, 논리적, 우연적

※ 응집도가 높을수록 좋은 설계이다.

정답 및 해설 보기
① 기능적(Functional) → ② 순차적(Sequential) → ③ 교환적(Communicational) → ④ 절차적(Procedural) → ⑤ 시간적(Temporal) → ⑥ 논리적(Logical) → ⑦ 우연적(Coincidental)
핵심: 응집도 암기법 — "기순교절시논우" (높음→낮음)
• 기능적: 단일 기능만 수행 (가장 높음 = 가장 좋음)
• 순차적: 한 활동의 출력이 다음 활동의 입력으로 사용
• 교환적(통신적): 동일한 입출력 데이터를 사용하는 활동들
• 절차적: 순서대로 수행되어야 하는 활동들
• 시간적: 같은 시간에 실행되는 활동들 (예: 초기화 모듈)
• 논리적: 유사 성격의 활동들을 하나로 묶음 (예: 입력 모듈)
• 우연적: 아무 관련 없는 활동들이 우연히 묶임 (가장 낮음 = 가장 나쁨)
문제 7
GoF 디자인 패턴 ★★★★

다음 설명에 해당하는 GoF 디자인 패턴의 이름과 분류(생성/구조/행위)를 쓰시오.

(1) 클래스의 인스턴스가 오직 하나만 생성되도록 보장하고, 어디서든 그 인스턴스에 접근할 수 있는 전역적 접근점을 제공하는 패턴

(2) 기존 클래스의 인터페이스를 다른 클래스가 사용할 수 있도록 변환해주는 패턴으로, Wrapper라고도 한다.

(3) 객체의 상태가 변경되면 그에 의존하는 모든 객체에 자동으로 통보되어 갱신되는 패턴 (일대다 의존 관계)

(4) 객체 생성을 서브클래스에 위임하여, 생성할 객체의 클래스를 결정하지 않고 객체를 생성하는 패턴

정답 및 해설 보기
(1) 싱글톤(Singleton) - 생성 패턴
(2) 어댑터(Adapter) - 구조 패턴
(3) 옵서버(Observer) - 행위 패턴
(4) 팩토리 메서드(Factory Method) - 생성 패턴
핵심: GoF 23개 패턴의 분류
• 생성(5개): 싱글톤, 팩토리메서드, 추상팩토리, 빌더, 프로토타입
• 구조(7개): 어댑터, 브리지, 컴포지트, 데코레이터, 퍼사드, 플라이웨이트, 프록시
• 행위(11개): 옵서버, 전략(Strategy), 커맨드, 상태(State), 템플릿메서드, 반복자(Iterator), 중재자(Mediator), 메멘토, 책임연쇄, 방문자(Visitor), 인터프리터

McCabe 순환복잡도 ★★★★

다음 코드의 McCabe 순환복잡도(Cyclomatic Complexity)를 구하시오.

int calculate(int a, int b) {
    int result = 0;
    if (a > 0) {
        if (b > 0) {
            result = a + b;
        } else {
            result = a - b;
        }
    } else {
        for (int i = 0; i < 3; i++) {
            result += i;
        }
    }
    return result;
}

(1) 제어 흐름 그래프에서 간선(E)의 수: (   )
(2) 제어 흐름 그래프에서 노드(N)의 수: (   )
(3) McCabe 순환복잡도 V(G) = (   )

※ 공식: V(G) = E - N + 2 또는 V(G) = 조건문(분기) 개수 + 1

정답 및 해설 보기
(1) E = 11   (2) N = 9   (3) V(G) = 11 - 9 + 2 = 4
핵심: McCabe 순환복잡도 계산법
• 간단 계산법: 조건문(if, for, while, case) 개수 + 1 = 3(if, if, for) + 1 = 4
• 공식: V(G) = E(간선) - N(노드) + 2
• 의미: 독립적인 실행 경로의 수. 값이 클수록 복잡한 프로그램
• 권장: V(G) ≤ 10이 바람직. 10 초과 시 모듈 분할 권장
• 시험 팁: 간단 계산법(분기문 수 + 1)을 먼저 적용하면 빠르게 풀 수 있음
